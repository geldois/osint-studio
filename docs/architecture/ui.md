# UI — what it does

The frontend's non-Whiteboard chrome (login, settings, ingest, account menu, theme toggle, view switch) is built
from shadcn/ui components vendored into `src/components/ui/`, generated by the shadcn CLI — `components.json`
pins the exact configuration — rather than hand-written Tailwind utility classes repeated per screen.

## Decisions

Base UI was chosen over Radix as the accessibility primitive underneath every interactive component: the project
had no existing Radix dependency creating inertia toward it, and Base UI is the primitive the shadcn CLI itself
promoted to default starting with its March 2026 rewrite. The "Nova" preset (Lucide icons, Geist font) was picked
because it already matched what this project used before adopting shadcn, not because it's the CLI's own
default.

The five pre-existing color tokens (`--background`/`--foreground`/`--surface`/`--border`/`--muted` in
`globals.css`) keep their original hex values rather than the CLI-generated palette. shadcn's own canonical
tokens that would otherwise duplicate them (`--card`, `--popover`, `--secondary`, `--accent`, and their
`-foreground` pairs) are pointed at `var(--surface)`/`var(--foreground)` instead of the CLI's own generated gray,
so every pre-existing `bg-surface` usage and every new `Card`/`Popover`/`DropdownMenu` render the same surface.
Every other generated token (`--primary`, `--destructive`, `--ring`, `--input`, `--chart-*`, `--sidebar-*`) is
exactly what the CLI generated for the `neutral` base color, left untouched.

The Whiteboard's own visual surface (`src/components/detail-panel/`, `src/components/data-table/`, the Whiteboard
header) now runs on the same component set — `Card`/`Button`/`Input`/`Table`/`ScrollArea` — once the chrome-screen
pass above proved the pattern held. `src/components/nodes/` and `src/components/edges/` keep their own custom
React Flow renderers, since no shadcn primitive maps to a graph node or edge.

A relationship edge's list of relationships renders inside a real `Popover`, opened by clicking the diamond
marker — a deliberate UX choice: relationships stay hidden until asked for, trading always-visible detail for a
quieter Whiteboard on graphs with many edges. Its one known gap: the popup doesn't track the diamond during an
active pan or zoom while it's already open, since Base UI's positioning follows scroll/resize/layout-shift but not
a pure CSS-transform move — closing and reopening it re-anchors correctly. Fixing that live-tracking case would
need shared state between the Whiteboard and every edge just to close the popover on pan-start, judged not worth
it for that narrow a window.

Theme is `next-themes` (`attribute="class"`, `defaultTheme="dark"`, `enableSystem={false}`) rather than the
project's own 40-line store it replaced. The defect that forced the swap was the flash of dark theme on every
load for a user who'd picked light: fixing it without the library means writing the same blocking pre-paint
script `next-themes` already ships, so keeping the hand-rolled store would mean maintaining both. `ThemeToggle`
reads `useTheme()` behind a `useSyncExternalStore`-based mount guard — not a `useEffect` + `setState` mount flag —
because the project's React Compiler lint rule flags synchronous `setState` inside an effect body.

## Consequences

shadcn's own `Card` component (`src/components/ui/card.tsx`) is a generic container, unrelated to this project's
own domain glossary's **Card** (a node's visual representation on the Whiteboard, `CONTEXT.md`) — the two names
coexist in different layers; see `CONTEXT.md`'s flagged ambiguities before assuming either sense.

Adding a component to any screen outside the Whiteboard means running the shadcn CLI (`pnpm dlx shadcn add
<component>`) against the pinned `components.json`, not hand-composing Tailwind classes — new primitives inherit
the token setup above automatically.
